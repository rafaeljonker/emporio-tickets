Guard hasNextPage && !isFetchingNextPage. NN/g: keep the button (footer reachable, keyboard fallback).
2. Delete: per-row useMutation (per-row isPending). onSuccess setQueryData over pages keeping pageParams; toast. Skip optimistic+rollback (TanStack: simple approach when shown in one place). invalidateQueries on infinite refetches all pages sequentially — heavy/jumpy. Local removal safe only with keyset cursor. Confirm: NN/g — name the item, outcome-labelled buttons ("Delete ticket"/"Cancel"); undo needs soft-delete → skip; AlertDialog.
3. Forms: useState controlled inputs + `schema.safeParse` with shared Zod schema, then mutate. Rejected RHF (dep for few lines), useActionState (made for Server Functions; auto-reset, queued, errors to boundary). errorFormatter with `z.flattenError(cause)` (Zod 4; tRPC docs still show .flatten()). Client: zodError.fieldErrors → fields; else err.message in role="alert" banner.
4. Edit page: server fetch in page.tsx; NOT_FOUND → notFound() (Server Components only). Don't try/catch-swallow notFound; `.catch(e => { if (e instanceof TRPCError && e.code==='NOT_FOUND') notFound(); throw e })`. Ticket → form initial state as props.
5. Feedback: sonner for transient results (aria-live polite in source); Toaster in root layout survives router.push. Field errors aria-invalid/aria-describedby; server errors role="alert" banner; no form errors in toasts. List: Suspense skeleton; error.tsx with reset "Try again"; next-page failure inline + retry fetchNextPage; empty state with "Create ticket" link.
